# Разбор исходного проекта

## Исходное состояние

Проект состоял из Next.js-приложения `front` и распакованного NestJS-проекта `cloud-storage-backend-master`. README содержал только название. Для приложений существовали отдельные npm-lock и дополнительный pnpm-lock; общего запуска, gitignore и схемы Supabase не было.

На клиенте использовались классы Tailwind без установленного Tailwind, большой общий CSS, inline-стили и шесть копий страниц категорий. Часть карточек показывала демонстрационные данные, а каталог — реальные строки Supabase.

Бэкенд одновременно подключал PostgreSQL/TypeORM с локальным JWT и Supabase Auth/Storage. Локальная регистрация сравнивала пароли открытым текстом, а токен этого механизма не подходил файловому Supabase guard. Клиент локальную авторизацию не использовал.

## Исправления

| Проблема                                                                         | Решение                                                                                              |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| API слушал 7777, загрузка шла на порт web 3000 без API-маршрута                  | Один HTTP-клиент и Next.js proxy `/api`                                                              |
| Каталог читал `models`, загрузка записывала `files`                              | Один API и контракт модели, включая имя, описание, категорию и владельца                             |
| Multer писал на диск, сервис ожидал `file.buffer`                                | Загрузка в память с ограничением размера во время приёма                                             |
| Обращение к приватному Supabase-полю через индекс                                | Один внедряемый серверный SupabaseService                                                            |
| Два несвязанных механизма аккаунтов и ненужное подключение PostgreSQL при старте | Supabase Auth; TypeORM и локальная JWT-регистрация выведены из приложения                            |
| Категория не участвовала в фильтрации                                            | Единый каталог с фильтрами категорий и форматов                                                      |
| При нулевом результате фильтра показывались все модели                           | Честное пустое состояние и сброс фильтров                                                            |
| Сортировка по популярности не работала, размер считался по полигонам             | Дата, название и размер файла                                                                        |
| Профиль использовал несовместимые версии Supabase API                            | Общий провайдер сессии, состояния загрузки и гостя                                                   |
| Избранное было заглушкой                                                         | Сохранение ID в браузере и реальные карточки                                                         |
| Кнопка добавления тестовой модели меняла облачную базу из каталога               | Удалена                                                                                              |
| Шесть копий категорий и недействующие utility-классы                             | Динамический маршрут, общая оболочка и адаптивный CSS                                                |
| Разрозненные модальные окна и отладочные alert/console                           | Общий native dialog, управление фокусом, Escape, встроенные сообщения форм                           |
| Сборка падала без Supabase-переменных                                            | Явная необязательная конфигурация для просмотра интерфейса; API возвращает 503 для облачных операций |
| Нет инструкции и структуры репозитория                                           | npm workspaces, один lockfile, env-примеры, схема и документация                                     |

Исходные изображения категорий сохранены. Существующий локальный `.env` и `uploads` перенесены вместе с бэкендом в `apps/api` и исключены из Git. Исходное удаление RAR-архива, уже присутствовавшее в рабочем дереве, не отменялось.

Изменения схемы и облачных данных не выполняются автоматически при запуске. Подключение к реальному Supabase и перенос старых файлов требуют конфигурации, описанной в README.
