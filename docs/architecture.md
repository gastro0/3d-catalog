# Устройство проекта

## Поток данных

1. Next.js отдаёт страницы и общий интерфейс. В проекте сохранён Pages Router.
2. Браузер использует Supabase SDK только для регистрации, входа, выхода и получения access token.
3. Запросы каталога идут на `/api/models`. Next.js проксирует их на NestJS, по умолчанию порт 7777.
4. API читает и записывает метаданные в таблицу Supabase `public.models`.
5. Файлы находятся в приватном Supabase Storage bucket. База хранит путь объекта, а не содержимое.
6. При скачивании API выдаёт ссылку на 60 секунд. Каталог и скачивание публичны. Загрузка и удаление требуют проверенного токена; удалить модель может её владелец.

Тема и язык сохраняются в localStorage. Избранное также хранится в браузере, синхронизируется между вкладками и не привязано к аккаунту.

## Маршруты

| Web                 | Назначение                                 |
| ------------------- | ------------------------------------------ |
| `/`                 | Каталог с поиском, фильтрами и сортировкой |
| `/models`           | Дополнительный адрес того же каталога      |
| `/models/:id`       | Карточка, скачивание и действия владельца  |
| `/categories`       | Все категории моделей                      |
| `/categories/:slug` | Каталог выбранной категории                |
| `/favorites`        | Локальное избранное                        |
| `/profile`          | Аккаунт и собственные модели               |

Старые URL `/architecture`, `/home`, `/decor`, `/toys`, `/animals`, `/games` перенаправляются на новые страницы категорий.

| API                        | Авторизация           | Действие                                           |
| -------------------------- | --------------------- | -------------------------------------------------- |
| `GET /health`              | Нет                   | Состояние процесса и наличие конфигурации          |
| `GET /models`              | Нет                   | Список метаданных                                  |
| `GET /models/:id`          | Нет                   | Одна модель                                        |
| `GET /models/:id/download` | Нет                   | Временная ссылка на файл                           |
| `POST /models`             | Supabase Bearer token | Multipart: файл, основные поля и метаданные модели |
| `DELETE /models/:id`       | Токен владельца       | Удаление файла и записи                            |
| `GET /swagger`             | Нет                   | OpenAPI                                            |

`storageConfigured` в health означает наличие настроек, а не успешное подключение к удалённому сервису.

## Границы модулей

- Компоненты оболочки не содержат запросов каталога.
- Провайдер сессии используется шапкой, входом, загрузкой и профилем.
- Категории и форматы объявлены в одном месте на клиенте; API независимо проверяет допустимые значения.
- Одна реализация каталога используется на общей странице, в категориях, избранном и профиле.
- API получает файл в память; Multer ограничивает размер во время приёма. Имя объекта генерируется через UUID и не содержит пользовательского пути.
- Если запись метаданных после загрузки не удалась, API удаляет объект из Storage.
- Перед удалением проверяется владелец. При ошибке Storage запись остаётся в базе, чтобы можно было повторить запрос.
- При отсутствии ключей API запускается и отдаёт health; обращения к хранилищу отвечают 503. Клиент не создаёт Supabase с фиктивными ключами.

## SQL и существующие данные

Миграция `202610210001_catalog_metadata.sql` выполняется после основной схемы. Она добавляет массивы `purposes`, `tags`, `features`, `software` и текстовые поля `license`, `dimensions`, `print_notes`, `file_contents`. Существующие записи и пути файлов не изменяются; неизвестные назначения и лицензии остаются пустыми. API принимает массивы как JSON-строки в multipart и проверяет списки, длину и количество значений. При чтении старой схемы до миграции каталог остаётся доступным без новых метаданных.

Каталог содержит 19 категорий. Старые названия сопоставляются с новыми при отображении, подсчёте и фильтрации; старые slug сохранены. Назначение модели не выводится из расширения файла. Форма допускает несколько назначений и необязательные характеристики, страницу модели и фильтры заполняют только сведения автора.

Поиск охватывает название, описание, теги и категорию, поддерживает небольшой словарь русских и английских синонимов. Поиск, фильтры и сортировка хранятся в query-параметрах URL. Ссылка модели содержит внутренний обратный адрес `from`, чтобы вернуть пользователя к прежней выдаче. Ненаполненные категории скрываются по умолчанию, когда в каталоге есть хотя бы одна наполненная категория; до первой загрузки доступны все направления. Количество моделей считается по реальным записям, ошибки загрузки не отображаются как нулевые значения.

`npm.cmd run test:catalog` проверяет согласованность клиентской и серверной классификации, поиск, комбинированные фильтры, старые категории, валидацию multipart, разметку пустых состояний, параметры скачивания и очистку файла при ошибке записи.

Миграция создаёт новую таблицу, если её нет. Для исходной схемы выполняет переименование `model_name → name`, `user_id → owner_id`, `filename → storage_path`, `size → file_size`, `preview_url → imageUrl`, сохраняя данные, типы, ограничения и пути объектов. Недостающие поля добавляются. Пустые названия дополняются из `original_name` или имени файла; формат приводится к верхнему регистру; категория старых моделей без классификации — «Без категории». Неиспользуемые старые поля сохраняются. Миграция выполняется в транзакции и допускает повторный запуск. Если одновременно существуют старое и новое имя одного поля, она останавливается для ручной проверки.

Автоматически при запуске приложения облачная схема не изменяется. Старые внешние клиенты, использующие прежние названия колонок, после миграции потребуют обновления.

Перед применением к существующему проекту сделайте резервную копию и проверьте:

- В таблице `models` есть первичный ключ `id`, принимающий UUID-строки: `text` или `uuid`. Числовой ID нужно мигрировать отдельно.
- `name`, `category`, `format`, `description` имеют текстовый тип; `polygons` и `file_size` — числовой; `owner_id` совместим с UUID; `created_at` — timestamp.
- Дополнительные обязательные поля старой таблицы не мешают вставке нового контракта. Исходные обязательные `user_id` и `filename` переименовываются в поля, которые заполняет API.
- RLS включается; права anon/authenticated меняются на чтение. Запись осуществляется серверным service role.
- Старые модели без `storage_path` остаются видны, но скачать их нельзя до привязки реального файла. Старые записи без `owner_id` нельзя удалить через интерфейс.
- Старые таблицы `users` и `files`, локальная папка `uploads` и существующие объекты Storage не удаляются. Автоматического переноса этих файлов в модели нет.
- Bucket по умолчанию называется `models`. При конфликте существующий bucket не изменяется: убедитесь, что он приватный и поддерживает нужный размер. Если используете другое имя, создайте соответствующий приватный bucket и укажите его в API.

## Ограничения

Полноценного интерактивного 3D-просмотра и генерации превью пока нет. Для записей без imageUrl показывается обозначенный placeholder. ZIP хранится и скачивается целиком, без распаковки на сервере. Поддерживаемые расширения проверяются, но содержимое модели не анализируется.

Список загружается целиком; поиск и сортировка выполняются в браузере. Для большого каталога потребуются пагинация и серверные фильтры. Рейтинга и учёта популярности нет, поэтому сортировка предлагается по дате, названию и размеру файла.

Storage и Postgres не образуют общую транзакцию. Компенсация очищает файл при ошибке вставки, но при недоступности самого Storage очистку потребуется повторить вручную. Если после удаления файла не удалилась строка, повторное удаление модели завершит очистку.

Лицензия указывается автором из списка Creative Commons и сопровождается ссылкой на её условия; для старых моделей она может быть не указана. Для публичного production потребуются модерация, rate limiting, мониторинг, резервное копирование и сканирование загрузок. Эти подсистемы не входят в текущую реализацию.
