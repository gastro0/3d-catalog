# Прогресс обучения API-автотестированию

Обновлено: 20 октября 2026.

## Цель

Самостоятельно писать API-тесты на Python + requests + pytest,
проверять успешные и ошибочные сценарии, применять простые фикстуры
и параметризацию, разбирать падения и объяснять код на собеседовании.
Ориентир: 8–12 осмысленных сценариев, без дублирования ради количества.

## Программа — 6 занятий

1. Минимальный Python: словарь, доступ к полям, assert; устройство GET /health.
2. Первый GET-тест /health через requests и pytest; статус, тело, timeout,
   намеренное падение и его объяснение. Далее — чтение каталога при готовности базы.
3. Негативные сценарии и параметризация: отсутствие авторизации,
   отсутствующая модель с корректным UUID; ошибки загрузки после подготовки авторизации.
4. Тело запроса и простые фикстуры: POST /models использует multipart/form-data
   (файл и поля), а не JSON. Bearer-токен разбираем до первого защищённого запроса.
5. Связанный сценарий: загрузка → получение → скачивание → удаление;
   очистка своих данных, при возможности — запрет удаления чужой модели.
   Метода обновления модели нет; добавлять его ради обучения не нужно.
6. Самостоятельная итоговая работа и мини-собеседование по написанному коду.

Первые два занятия — ориентировочно по часу, остальные — 60–90 минут.
Переход определяется выполнением заданий и пониманием, а не таймером.

## Подготовка наставником

- Коротко изучены README.md, docs/architecture.md, контроллеры, сервис каталога,
  валидация загрузки и проверка авторизации. AGENTS.md и готовые тесты не найдены.
- Стек: Next.js/React, NestJS, Supabase Auth/Postgres/Storage.
- Установлены Node.js 22.14.0, npm 10.9.2, Python 3.10.2, requests и pytest.
- Команда запуска API: `npm.cmd run dev:api`; всего сайта: `npm.cmd run dev`.
- На порту 7777 уже работает API. Проверен только GET /health:
  HTTP 200, {"status":"ok","storageConfigured":true}.
- Запуск второго экземпляра завершился EADDRINUSE, его watcher остановлен.
  Ограниченная среда не видит локальный сервер; проверка health выполнена с расширенными правами.
- Swagger: http://127.0.0.1:7777/swagger.
- storageConfigured означает наличие настроек, а не проверку подключения.
  Работоспособность БД, миграция и назначение подключённого Supabase не проверены.
  До изменяющих запросов нужно установить, что это отдельное тестовое окружение.
- Поведение реализации — источник наблюдений, а не замена требованиям.
  Для /health используем описанное в архитектуре назначение и текущий ответ;
  неизвестные ожидания согласуем отдельно.
- Код приложения и учебные тесты наставником не изменялись.

## Текущее задание

На учебном Python-словаре
`health = {"status": "ok", "storageConfigured": True}`
достать поле status в переменную actual_status и через assert проверить,
что оно равно строке "ok". Прислать свои строки кода в чат.
Это упражнение со словарём, без HTTP-запроса и без готового автотеста.

Следующий шаг: дождаться решения, разобрать его, при ошибке дать подсказку
и возможность исправить самостоятельно. После правильного решения задать
один короткий вопрос по коду. Затем продолжить занятие 1.
